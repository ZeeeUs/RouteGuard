# Настройка RouteGuard

Русский · [English](CONFIGURATION.en.md)

## Свободное место

Перед установкой проверьте доступное место:

```sh
df -h /overlay /tmp
```

- **`/overlay` — от 16 МиБ свободно.** Это рекомендуемый запас для установки, сохранённых снимков правил и обновлений RouteGuard при уже установленных `firewall4`, `ca-bundle` и `luci-base`. В измеренной сборке ARM64 несжатые файлы двух пакетов занимают около 6,5 МиБ. Расход места на устройстве зависит от файловой системы и прошивки.
- **`/tmp` — от 16 МиБ свободно.** Установщик скачивает сюда оба APK. Локальные сборки для пяти архитектур весят около 2,6–3,0 МиБ на пару APK, а запас нужен для временных файлов установки. На большинстве устройств OpenWrt `/tmp` находится в оперативной памяти.

Если `apk` предстоит установить недостающие зависимости, выделите дополнительное место под их пакеты и установленные файлы. Для индексов репозиториев также может потребоваться дополнительное место. [Замеры размера и памяти](RESOURCES.md).

## Ручная установка и настройка

Скопируйте APK движка для архитектуры из `/etc/apk/arch` и общий APK LuCI в `/tmp` роутера. Для локальных APK без доверенной подписи используйте `--allow-untrusted` только для сборки, которую вы контролируете. В примере ниже используется `aarch64_cortex-a53`.

```sh
cd /tmp
apk update
apk add --allow-untrusted ./routeguard-aarch64_cortex-a53.apk ./luci-app-routeguard.apk
/etc/init.d/rpcd restart
```

При несовпадении имён используйте имена из каталога сборки. После установки откройте **Службы → RouteGuard** или войдите в LuCI заново. Через SSH проверьте реальные устройства выхода. Маршруты с policy routing и резервные WAN проверяйте отдельно.

```sh
ip -4 route show default
ip -6 route show default
ubus call network.interface.wan status
ip link show
```

В настройках Firewall выключите software и hardware flow offloading и примените изменение. Потоки с offloading могут обойти обычные hooks nftables. RouteGuard отклоняет применение, если видит настройки offloading fw4 или активную таблицу потоков nftables любой семьи.

Создайте и включите нужные профили, укажите WAN-устройства и явно выберите режим IPv6. Если используете домены или удалённые списки, укажите IP DNS-резолвера. При необходимости внесите IP сервера туннеля как исключение. Исключение относится ко всем профилям и портам этого IP. При смене IP сервера обновите исключение. Нажмите **Save & Apply**: форма сохраняет настройки RouteGuard, запускает применение и ждёт результат именно этой операции. Если применить правила не удалось, интерфейс показывает ошибку и сохраняются прежние рабочие правила. Если правила применены, а cron не удалось настроить, операция завершается с предупреждением. Кнопка **Refresh active addresses** обновляет адреса уже применённой конфигурации. Чтобы включить почасовое обновление, задайте минуту в поле **Hourly update minute**. Пустое поле оставляет обновление ручным. Для расписания включите системную службу cron.

### Пример UCI

```uci
config settings 'main'
	option enabled '1'
	option ipv6 'off'
	list wan_device 'pppoe-wan'

config service 'example'
	option enabled '1'
	option label 'My service'
	list ip '192.0.2.10'
```

Замените WAN-устройство и IP на свои. Для целей по доменам добавьте `option dns` в настройки и `list domain` или `list url` в профиль. После редактирования через UCI выполните `uci commit routeguard` и `routeguard apply`. При редактировании файла `/etc/config/routeguard` достаточно `routeguard apply`.

Конфигурация строго проверяет типы полей и логические значения. Для `enabled` допустимы `1/0`, `true/false`, `yes/no`, `on/off`, `enabled/disabled`; опечатка вызывает ошибку. Если от ранней сборки остался `option preset`, замените его явно настроенными целями.

## Удалённые списки доменов

Добавьте прямую HTTPS-ссылку в **Settings → профиль → Remote HTTPS domain lists**, укажите **DNS server**, включите профиль и нажмите **Save & Apply**. На GitHub прямую ссылку можно получить кнопкой **Raw**.

| Источник                                       | Прямая ссылка на текстовый список                                                                         |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| v2fly domain-list-community                    | [Anthropic](https://raw.githubusercontent.com/v2fly/domain-list-community/master/data/anthropic)          |
| Коллекция `allow-domains`, используемая Podkop | [Discord](https://raw.githubusercontent.com/itdoginfo/allow-domains/refs/heads/main/Services/discord.lst) |

Эти ссылки можно вставить прямо в поле. Они ведут на списки разных сервисов, поэтому для раздельной защиты заведите два профиля. Когда несколько источников описывают один сервис, добавьте их в один профиль через **+**, по одной ссылке на строку.

- RouteGuard принимает текст с одним доменным именем на строку. Поддерживаются комментарии `#` и префиксы `domain:` и `full:`. Имена разрешаются буквально, поэтому нужные поддомены добавляйте отдельными записями. Записи `include:`, `regexp:`, `keyword:` и строки с атрибутами вроде `@telemetry` пропускаются. Для коллекций с несколькими форматами выбирайте текстовый список доменов. Бинарные `geosite.dat`, `.srs`, `.mrs` и конфигурации dnsmasq не поддерживаются.
- На профиль можно добавить до четырёх ссылок. Лимит размера каждого файла — 128 КиБ. Общий лимит — 256 уникальных доменов во всех активных профилях. Списки и ручные домены объединяются до DNS-запросов. Регистр и завершающая точка при удалении дублей не учитываются. `example.org` и `api.example.org` остаются отдельными именами. На вкладке **Status** колонка **Unique domains** показывает число уникальных доменов профиля.
- RouteGuard проверяет сертификат HTTPS и отклоняет редиректы. Если источник недоступен, файл пуст или содержит некорректную запись, RouteGuard сохраняет прежние правила. Содержимое внешних списков может меняться, поэтому перед применением проверьте, какие домены в них входят.

По умолчанию ссылки на удалённые списки принимаются только для публичных IP. Для доверенного внутреннего списка root может добавить строку с точным именем из URL и разрешённым IP-префиксом в `/etc/routeguard/private-list-hosts`, например `lists.example.net 10.0.0.2/32`. Проверка сертификата HTTPS действует и для таких источников.

### DNS и IPv6

- DNS запрашивается напрямую у указанного резолвера. Ошибка DNS, синтетические ответы DNS из `198.18.0.0/15`, битый или пустой список либо профиль без пригодных адресов оставляют прежние правила. При `NXDOMAIN` или пустом ответе A/AAAA плановое и ручное обновление активных адресов сохраняет последний известный результат для этого имени и семейства на срок до 24 часов с первого пустого ответа. Кэш наполняется при успешном получении адресов после обновления пакета.
- `ipv6=off` оставляет IPv6 без фильтрации RouteGuard. `ipv6=selective` включает AAAA и ручные IPv6-адреса/CIDR. При разных устройствах выхода для IPv4 и IPv6 добавьте оба.
- Клиенты могут получить другие IP из-за CDN, географии, выбора резолвера и времени запроса. Неизвестные IP проходят. Общий IP CDN может затронуть соседний сервис. Маршрут через устройство вне выбранных WAN проходит. RouteGuard фильтрует трафик, проходящий через этот роутер.

## Состояние, откат и удаление

```sh
routeguard status
logread -e routeguard
nft list table inet routeguard
routeguard rollback
```

Откат восстанавливает предыдущий активный снимок и ставит cron-обновления на паузу. `routeguard apply` применяет текущую UCI-конфигурацию и возобновляет расписание, если указана минута обновления. Перед признанием правил неизменными RouteGuard проверяет цепочки, приоритеты, порядок правил, WAN-селекторы и содержимое наборов адресов в ядре. Повреждённая или неполная таблица восстанавливается. При неизменных исправных правилах счётчики сохраняются. Они начинаются заново при замене таблицы и перезагрузке.

Чтобы снять правила, выставьте `routeguard.main.enabled=0`, сохраните конфигурацию и выполните `routeguard apply`. Для удаления остановите службу до удаления пакетов. UCI и сохранённые снимки можно оставить для переустановки. Переустановка со старым снимком восстанавливает его при старте. Если это нежелательно, перед удалением отключите RouteGuard через UCI и примените изменение.

```sh
/etc/init.d/routeguard stop
apk del luci-app-routeguard routeguard
nft list table inet routeguard
```

Последняя команда должна сообщить, что таблица отсутствует. Для полного удаления сохранённого состояния удалите `/etc/routeguard/state.json` и, если существует, `/etc/routeguard/state.json.pending` после остановки службы. Пакет меняет только свою таблицу и свою строку в root crontab. Обычные `fw4 reload` и `fw4 restart` используют таблицу `inet fw4`. Глобальный `nft flush ruleset` сносит и RouteGuard. Для восстановления из локального снимка используйте **Status → Restore saved rules** или `routeguard restore`. Если таблица исчезла, обновление сначала восстанавливает снимок, затем обращается к источникам адресов. [Реализация команд fw4](https://lxr.openwrt.org/source/firewall4/root/sbin/fw4)

## Профили и состояние в LuCI

Введите имя в поле **New profile name** и нажмите **Create profile**. Имя станет заголовком секции. Новые профили выключены до явного включения **Protect this profile**; общий переключатель **Block direct connections** управляет применением защиты. Существующие профили и их настройки сохраняются.

**Internet uplink devices** — выпадающий список устройств подключения к Интернету (`wan`, `pppoe-wan`) с выбором нескольких устройств. Список загружается из LuCI; ранее выбранное временно отсутствующее устройство сохраняется, его также можно указать вручную. Выбирайте внешние подключения, а не LAN или туннель. **DNS server** — DNS-сервер для получения реальных адресов доменов: выберите Cloudflare, Google или Quad9 из выпадающего списка либо введите собственный IPv4/IPv6-адрес в том же поле. Сервер по умолчанию не задан; для профилей только с IP поле можно оставить пустым.

Раздел **Protection status** показывает применённые правила, расписание и результат последней операции, состав активных профилей и счётчики блокировок отдельно для клиентов LAN и роутера. Не сохранённые изменения формы в этот статус не входят. Время отображается в часовом поясе браузера.

Команда `routeguard status` выводит JSON с отступами в два пробела. Структура полей не изменилась; вывод остаётся пригодным для JSON-парсеров и RPC.

## Вкладки и диагностика

RouteGuard содержит вкладки **Settings**, **Status** и **Diagnostics**. На вкладке Settings сначала расположены общие настройки, затем профили защиты; кнопка **Save & Apply** применяет их вместе. На вкладке Diagnostics кнопка **Check all profiles** запускает последовательные TCP-подключения с роутера на порт 443 реальных адресов, с привязкой к каждому выбранному WAN-устройству. Прокси из окружения не используются; туннель и правила firewall не изменяются.

Проверяется применённая конфигурация. При неподтверждённых правилах, offloading, незавершённом восстановлении или настройках, отличающихся от применённых, проверка не запускается. Одновременно с ней другие операции RouteGuard не выполняются.

Для каждого профиля при обновлении адресов сохраняется до одного тестового адреса IPv4 и IPv6. Адреса исключений не выбираются. Произвольные хосты из ручных CIDR не сканируются. После обновления со старой версии сначала выполните обновление адресов на вкладке Status. Выключенные профили и профили без подходящего адреса получают результат «Not tested».

Результаты — **Connection succeeded**, **Drop observed**, **Inconclusive**, **Not tested**. Успешное TCP-подключение означает, что проверка не встретила ожидаемую блокировку; локальное перенаправление трафика может изменить путь подключения. Тайм-аут без прироста счётчика не считается успехом защиты. Прирост общего счётчика OUTPUT фиксирует наблюдаемую блокировку, но может включать фоновый трафик. Это выборочная диагностика, не гарантия для всех адресов, портов, UDP, клиентов LAN и доступности туннеля.

Один запуск ограничен 32 пробами и 90 секундами, одно подключение — двумя секундами. Сетевых запросов к сайтам на уровне HTTP и TLS нет. Результат хранится с идентификатором операции в оперативном каталоге `/var/run/routeguard/jobs`, без постоянного демона и записей диагностических результатов во flash. Запуск из CLI: `routeguard queue diagnose`, чтение результата: `routeguard job ID`.
