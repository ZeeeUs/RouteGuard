# Размер и память

Замер от 11 ноября 2026 года, Go 1.27.4, Linux ARM64, nftables 1.1.3. Полные результаты и параметры окружения: [results/linux-arm64.json](results/linux-arm64.json).

| Показатель                                     | Обычная конфигурация | Максимальная конфигурация |
| ---------------------------------------------- | -------------------: | ------------------------: |
| Профили / домены / адреса                      |     1 / 16 / 64 IPv4 |       8 / 256 / 4096 IPv6 |
| Пик RSS при применении, максимум из 3 запусков |            15,55 МиБ |                 17,75 МиБ |
| Пик RSS команды статуса                        |            10,03 МиБ |                 16,35 МиБ |
| Пик RSS отдельного `nft -f`                    |             4,43 МиБ |                 10,30 МиБ |

Бинарник Linux ARM64 занимает **6 815 904 байта (6,50 МиБ)**. Несжатое содержимое двух пакетов до упаковки — около **6,51 МиБ**, без системных зависимостей. Размер APK проверяется отдельно при SDK-сборке; он не равен занятому месту в `/overlay`.

Проверенная SDK-сборка: APK движка — **2 759 087 байт (2,63 МиБ)**, APK LuCI — **4800 байт**. После штатной обработки SDK установленный бинарник занимает 6 797 464 байта, суммарные файлы обоих APK — 6 807 604 байта (6,49 МиБ). Файловая система и зависимости добавляют собственные расходы. Контрольные суммы и результаты установки: [results/openwrt-25.12.5.json](results/openwrt-25.12.5.json).

## Методика

```sh
make resources TARGET_ARCH=arm64
```

Сценарий запускается в отдельном Docker-контейнере без внешней сети. Он поднимает локальные DNS и HTTPS с тестовым сертификатом. Обычный профиль получает 64 IPv4-адреса для 16 доменов. Максимальный использует 32 WAN-устройства, 8 профилей, 256 доменов, 4096 различных IPv6-адресов, 128 исключений, 512 ручных адресов и 4 URL на профиль. Файл каждого источника достигает лимита 128 КиБ.

Три применения включают первое изменение и повторные проверки уже установленной полной таблицы. Отдельно измеряются статус, проверка nft и фактическая загрузка nft. Результат сохраняется в `build/resources.json`; превышение бюджета завершает проверку ошибкой. Для x86_64 используется `TARGET_ARCH=amd64`.

GNU `time %M` показывает наибольший RSS процесса команды с учётом дочерних процессов. Это **не одновременная сумма RSS дерева процессов и не память таблиц ядра**. Значения зависят от работы GC, архитектуры и ядра; большой профиль не обязан иметь больший RSS на каждом отдельном запуске. Числа выше — результат конкретного прогона, а не обещание для любого роутера.

## Регрессионные бюджеты

Единый источник порогов — `tests/resource-budgets.json`:

- бинарник — до 8 МиБ;
- несжатое содержимое пакетов без зависимостей — до 9 МиБ;
- пик RSS команды — до 32 МиБ;
- отдельный процесс nft — до 16 МиБ;
- APK движка — до 4 МиБ.

Это верхние пороги для выявления регрессий. Мягкий бюджет Go в 12 МиБ управляет GC и не ограничивает весь RSS. Между операциями постоянного процесса RouteGuard нет. Открытая страница LuCI запрашивает статус раз в 10 секунд; результаты последних 16 операций хранятся в `/var/run`.

Окончательные замеры flash, общего RAM и таблиц ядра на конкретном OpenWrt выполняются по [OPENWRT-TEST.md](../OPENWRT-TEST.md). Замер Linux-контейнера такую проверку не заменяет.
